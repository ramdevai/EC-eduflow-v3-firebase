- Known limitation: "Send registration" / other WhatsApp actions (`openWhatsApp` in `lib/messaging-utils.ts`, and `DrawerPartnershipForm.tsx`) always open a new WhatsApp Web tab, even when one is already open and logged in, despite both call sites using a shared named window target (`window.open(url, 'eduflow-whatsapp')`). Root cause: `wa.me` redirects to `web.whatsapp.com`, which sets `Cross-Origin-Opener-Policy: same-origin`. That isolates the opened tab into a new browsing-context group, severing the opener's link to it, so a later `window.open` with the same window name can no longer find it and opens a fresh tab instead. This is enforced by WhatsApp's servers and cannot be fixed from this codebase's JS; it reproduces for any URL that ends up on `web.whatsapp.com`. The "Open in App" WhatsApp option (native `whatsapp://` protocol handler) is unaffected since it never opens a browser tab.
